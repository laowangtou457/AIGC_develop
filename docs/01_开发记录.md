## 3. 关键决策记录（ADR）

### ADR-1：集成方式选择后端服务集成而非 ComfyUI 节点

**背景**：H3 插件原生形态是 ComfyUI 自定义节点（Node 图内执行）。AI-NovelFlow 有两条执行通道：ComfyUI 工作流（JSON）与后端 LLM 服务。

**选项**：
- A：把 H3 节点装进 ComfyUI custom_nodes，让 NovelFlow 的工作流 JSON 调用它（分镜/提示词通过 ComfyUI 执行）
- B：把 H3 规则引擎与纯函数移植到 NovelFlow 后端，作为服务方法（Python 直调）

**决策**：B。

**理由**：
1. 分镜/提示词是**纯文本 LLM 链路**，与生图/生视频的 ComfyUI 图执行无关；放进 ComfyUI 反而引入"LLM 输出如何回传 NovelFlow 前端/数据库"的接线问题
2. B 可直接复用 NovelFlow 的 LLMService（统一配置/日志/错误），A 需要 H3 自带 urllib 通道另配密钥
3. B 可落库、可前端直连、可单元测试，闭环最短，符合"替换原本功能"的语义

### ADR-2：LLM 通道复用 LLMService

**背景**：H3 插件 `call_llm` 是 urllib 直连 OpenAI 兼容接口（默认 DeepSeek，config.json 存密钥）。NovelFlow 有完整 LLMService（读 system_configs 表）。

**决策**：`H3ManjuService._chat()` 调用 `LLMService.chat_completion(system_prompt, user_content, ...)`，H3 规则文件仍作为 system prompt 来源。

**理由**：配置单源（用户只需在系统设置配一次 LLM）；NovelFlow 有 LLM 日志（llm_logs）、温度/最大 token 统一管理；避免两套密钥并存。

### ADR-3：分镜落库映射现有 shots 表

**背景**：H3 分镜 JSON（shots[] + assets）与 NovelFlow Shot 表字段高度同构，但 H3 有额外字段（time_range/camera/mood/shot_size/purpose/continuity）。

**决策**：映射写入 `shots` 表（description/video_description/characters/scene/props/duration/dialogues），H3 完整 JSON 冗余存 `chapters.parsed_data`（键 h3_storyboard / h3_assets）。

**理由**：不迁移数据库（SQLite 无 ALTER 风险）、不破坏现有生图/生视频链路（它们消费 shots 表同一批字段）、提示词阶段可随时取回完整分镜。

### ADR-4：保留原"AI 拆分"功能

**背景**：用户要求"替换原本功能"。

**决策**：H3 作为推荐路径新增按钮；原"✨ AI 拆分"保留。

**理由**：灰度替换、可对比可回退；若 H3 链路在用户侧 LLM 配置或规则偏好上有问题，原链路仍可用；符合"不破坏原功能"的非功能需求。

### ADR-5：规则文件整体移植而非重写

**决策**：`rules/` 全部文件原样复制进 `h3_prompt_builder/`，`build_manju_system_prompt` 按文件名读取。

**理由**：规则文件是 H3 插件积累的核心资产（导演级约束、情绪外化表、运镜规则、逐镜提示词要求），重写会引入语义漂移；原样移植保证行为与 ComfyUI 端一致。

### ADR-6：mapping 默认空对象

**背景**：逐镜 H3 提示词需要"角色↔图号"映射（`<Picture N>` 接线）。前端目前未做映射编辑 UI。

**决策**：`h3-prompt-all` 接受 `mapping_json`，未传则默认 `{}`（无参考图场景）。

**理由**：保证文字链路（无参考图也能出提示词）可独立验收；映射 UI 列为后续工作。

## 4. 问题与解决记录

### P1：系统默认 Python（3.14）缺少 fastapi
- **现象**：`python -c "import fastapi"` → ModuleNotFoundError
- **排查**：`py -0p` 列出本机 Python：3.13（WindowsApps，无依赖）、3.12（Programs，fastapi 0.109/sqlalchemy 2.0.25 已装）
- **解决**：统一使用 `C:\Users\ghgh\AppData\Local\Programs\Python\Python312\python.exe`；确认这是用户原部署环境
- **教训**：多 Python 并存时以依赖探测为准，不猜默认解释器

### P2：PowerShell 字符串替换多行代码块易出错
- **现象**：在 PowerShell 命令内嵌 here-string + 表达式组合时解析失败（`@'` 未闭合）
- **解决**：改用 Python 脚本（UTF-8 读写）做文件级字符串替换，可靠且可复现
- **教训**：复杂文本替换走脚本文件，不用交互式 shell 内联

### P3：POST /novels 返回 307
- **现象**：测试脚本创建小说接口返回 307（路由重定向）
- **排查**：路径末尾斜杠问题（`POST /` 与路由定义 `@router.post("/")` 的斜杠规范）
- **解决**：改用数据库中已有测试小说「小红帽（章回体版）」（AI 测试用例自带 5 章），不新建测试数据
- **影响**：无——测试数据无污染

### P4：LLM api_key 为空（环境限制，非代码缺陷）
- **现象**：h3-split 全链路调用后 LLM 返回 `401 Authentication Fails (governor)`
- **排查**：system_configs 表 `llm_api_key=None`；供应商/模型/URL 均已配置
- **解决**：确认是用户侧配置缺口；代码链路已全部打通。在交付说明中明确"需在系统设置填写 API Key"
- **影响**：文字链路功能完整，但实际生成需用户填 key

### P5：Edit 工具对 CRLF/BOM 文件匹配失败
- **现象**：`Edit` 工具 OLD_STRING_NOT_FOUND（文件实际为 UTF-8 无 BOM + CRLF）
- **解决**：改用 `[IO.File]::ReadAllText/WriteAllText` + 精确子串替换，或 Python 脚本
- **教训**：Windows 上混合工具链时优先脚本化替换

### P6：浏览器打开章节生成页初始"加载中"
- **现象**：navigate 到 `/generate` 后 get_page_text 仅"加载中"
- **解决**：等待 6 秒后重新 snapshot，页面完整渲染（含 H3 按钮）
- **教训**：SPA 首屏有异步数据加载，需等待后再断言
