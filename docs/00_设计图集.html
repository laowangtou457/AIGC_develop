1. 项目概述

1.1 背景

用户已具备两个独立项目：

项目作用原始路径
**AI-NovelFlow**AI 驱动的小说转动画/视频工作流平台（FastAPI + React），已成功部署运行`D:\AIGC\AI_NovelFlow\AI-NovelFlow`
**ComfyUI-H3-Prompt-Builder**MiniMax H3 视频提示词构建 ComfyUI 插件，含"剧本→分镜剧本→逐镜 H3 提示词"漫剧流水线`D:\AIGC\develop\ComfyUI-H3-Prompt-Builder`

用户要求：在备份副本基础上，将 H3 插件的漫剧分镜能力集成进 AI-NovelFlow，替换原有"编辑章节→生成文字分镜→生成分镜提示词"链路，形成符合目标工作流结构（小说转视频工作流.html）的独立工作流，并最终可本地启动访问、实现具体功能。

1.2 目标工作流结构（来自用户上传 HTML）

主流程（6 步，单向推进）： 导入小说 → 生成剧本 → 编辑章节 → 生成文字分镜 → 生成分镜提示词 → 生成视频 并行执行区间（与主流程「生成剧本→生成分镜提示词」同步）： AI解析角色 ─→ 生成角色图 ─┐ AI解析场景 ─→ 生成场景图 ─┼─→ 角色/场景/道具素材注入 ──→ 生成视频（虚线汇入） AI解析道具 ─→ 生成道具图 ─┘

• **不改动原仓库**：全部修改在 `New_AI_Production_Workflow` 副本内完成
• **替换语义**：H3 链路作为"生成文字分镜 / 生成分镜提示词"的新实现；原"AI 拆分"保留但降级为可选项

4. 设计理念

4.1 关键决策（ADR 摘要）

决策选项结论理由
D1 集成方式A. ComfyUI 自定义节点；B. 后端 Python 服务集成**B**分镜/提示词是纯 LLM 文本链路，与生图/生视频的 ComfyUI 执行链路解耦；后端集成可直接复用 NovelFlow 的 LLM 配置、落库与前端状态，闭环最短
D2 LLM 通道A. H3 自带 urllib 直连；B. 复用 LLMService**B**用户已在 AI-NovelFlow 系统设置配置 LLM，避免二次配置与多套密钥；LLMService 提供统一日志与错误处理
D3 分镜存储A. 新增表/字段；B. 映射到现有 shots 表 + parsed_data**B**不迁移数据库、不破坏现有生图/生视频链路；H3 分镜 JSON 冗余存于 chapter.parsed_data 供提示词阶段取用
D4 原功能去留A. 删除原拆分；B. 保留**B**灰度替换，便于对比与回退；UI 上 H3 为推荐路径
D5 规则来源A. 重新编写提示词；B. 直接移植 H3 规则库**B**规则文件是 H3 插件的核心资产（分镜导演/逐镜提示词/风格），整体复制保持语义一致

4.2 设计原则

• **最小侵入**：新增文件独立成包（`h3_prompt_builder`、`h3_manju_service.py`、`h3_workflow.py`），对既有文件仅做路由注册与 UI 追加。
• **配置单源**：LLM 供应商、模型、密钥一律取自 `system_configs` 表，H3 服务不持有独立密钥。
• **可回退**：原"AI 拆分"按钮保留；H3 失败不影响系统其他功能。
• **字段可映射**：H3 分镜 JSON 与 `shots` 表字段一一对应，`parsed_data` 冗余保存原始 JSON 以便提示词阶段与排障。

7. 规则引擎设计

7.1 规则文件

文件用途关键要求（摘录）
`manju_storyboard.txt`剧本→分镜节拍分析 3-8 个；单镜 2-5 秒；镜头数×时长≈目标时长；时间轴连续无空洞；每镜必填 purpose/continuity/screen_direction；动作具体到肢体、禁止抽象动词；情绪外化表 10 种
`manju_shot_prompt.txt`分镜→逐镜 H3 提示词按本镜数据生成 H3 提示词；`<Picture N>` 标签重编号（≤9 张）；缺失资源提示
`base_system_prompt.txt`通用基础规则H3 提示词官方结构要求
`styles/*.txt`风格规则极简产品广告/3D 动画短片/纸艺定格等 8 种

7.2 引擎纯函数

• `compute_shot_refs`：聚合镜头角色/场景/道具 → 查 mapping 图号 → 按图号升序重编 `<Picture 1..N>`；检测缺映射与图号冲突（>9 张告警）
• `build_wiring_note`：生成该镜接线说明（`<Picture 1>=角色A（图库第 3 张）`）
• `parse_mapping_text`：解析"角色A=图1"多行文本 → mapping JSON + 重复/缺失告警
• `_extract_json`：剥离 ``` 代码块标记后抽取首个 JSON 对象

10. 接口契约

方法路径请求体成功响应

13. 已知限制与后续工作

已知限制

• **H3 单段 15 秒上限**：模型能力上限（帧数 124–362 @24fps），超长走分段拼接（15s×N）
• **生图默认 Flux2-Klein-4B**：9B 显存占用过高已弃用；动漫/写实风格走 SDXL 底模模板
• **管线 VLM 降级**：Ollama 未启时画面描述为"待补充"，不阻断
• **ASR 默认 tiny**：追求准确率可换 base/small（更慢）
• **复杂武打动作受限**：受视频模型能力限制，靠多关键帧 + 分段拼接补偿

14. 平台扩展：三大工作流设计（v2.0）

14.1 工作流② AI 武术指导（martial_arts）

一句话需求（+参考图上传） → 需求解析(qwen3:30b-a3b / qwen2.5vl 解析参考图) → 人物锚定卡（多角色，英文） → 16宫格武打分镜提示词 → 角色形象图（文生图 Flux2-4B） → 分镜图（图生图 single_image_edit） → 武打视频（图生视频 H3 ref2va / 首尾帧 / 多关键帧） → 历史任务留存
• 接口：`POST /api/martial-arts/generate-image`（文生图）、`edit-image`（图生图）、`generate-video`（图生视频）
• 关键实现：`_build_flux2_4b_text2img_workflow`（动态拼节点链）、`_ensure_comfyui_input_filename`（output→input 目录搬运，规避 LoadImage 400）、`_free_comfyui_cache`（视频前 /free）、`cardToText`（锚定卡→纯文本）
• 历史任务持久化：任务/角色/分镜图/视频/时间戳，刷新不丢

14.2 工作流③ 视频资源替换（video_asset）

上传参考成片 → 子进程调用管线 run_all.py（--asr-model tiny --platform minimax_h3） → 镜头切分(scenedetect) + 关键帧 + ASR台词 + VLM画面描述(qwen2.5vl) → 资产抽取(角色人脸/场景/道具) → 多平台逐镜提示词导出 → 资产替换(覆盖 assets.json 参考图，原图备份 .orig.bak) → 重跑阶段4 → ZIP打包下载
• 架构决策：**隔离调用**（子进程 + 独立 venv）、**产物即接口**（只读 JSON + 静态文件服务，可中断续跑）、**目录穿越防护**（resolve 前缀校验 403）
• 端点：`/api/video-asset/analyze`、`jobs`、`jobs/{id}`、`jobs/{id}/files/{path}`、`jobs/{id}/download`、`jobs/{id}/swap-asset`
• 数据模型：`VideoAssetHistory`（video_name/status/stage/output_dir/summary_json/error/时间戳）
• 产物：`prompt_pack.md`（seedance/kling/veo/jimeng）+ `minimax_h3/`（prompts.md 六段式 + payloads + assets_manifest + validation_report）

14.3 显存治理（GPU 串行调度）

• `gpu_scheduler.py` 全局锁：同刻只跑一个模型任务
• Ollama `keep_alive:0`：ComfyUI 排队时自动卸载 LLM
• 视频生成前 ComfyUI `/free`（unload_models + free_memory）
• 解析 → 卸载 LLM → 生图 串行，避免 OOM 死锁
