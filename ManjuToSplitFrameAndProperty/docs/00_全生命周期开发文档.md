# 00 全生命周期开发文档（漫剧抽帧与属性管线）

> 版本：v1.0.0 ｜ 工程：`ManjuToSplitFrameAndProperty` ｜ 定位：New_AI_Production_Workflow 漫剧工作流生态的"视频逆向"模块

---

## 1. 需求分析

### 1.1 背景与定位

漫剧（动态漫画/短剧）工业化生产中，从**参考成片**逆向出分镜结构、台词剧本与角色/场景资产，
再通过 AI 视频模型（MiniMax H3 等）**以替换资产的方式再生成新成片**，是核心提效路径。

本工程承接该链路的前半段（逆向）与导出端（生成提示词），并满足：
- **独立可运行**：纯 CLI，不依赖任何云服务（ASR/VLM 可选）。
- **可集成**：模块化设计，可被 ComfyUI 以自定义节点方式加载，也可被 AI-NovelFlow 后端服务调用。
- **可审计**：全程结构化 JSON 产物，数据契约明确（schemas/），资产合规校验内置。

### 1.2 用户故事

| 编号 | 用户故事 | 验收标准 |
|---|---|---|
| US-1 | 作为漫剧编导，我上传一段自有成片，希望自动切出镜头和关键帧 | 产出 shots.json，镜头边界可复核 |
| US-2 | 我希望镜头里自动带上台词与画面描述 | storyboard.json 含 dialogue/visual 字段 |
| US-3 | 我希望把主要角色与场景抽成可复用资产 | assets.json 含角色裁片与场景图 |
| US-4 | 我希望逐镜头生成可直接提交 MiniMax H3 的提示词与 payload | minimax_h3/ 六段式提示词 + API payload |
| US-5 | 我希望也能导出 Seedance/Kling/Veo/即梦 的提示词 | prompt_pack.md 通用格式 |
| US-6 | 我希望在 ComfyUI 里以节点方式使用上述能力 | comfyui_nodes.py 5 个节点 + 示例工作流 |
| US-7 | 我希望产物不触碰版权红线 | 每次导出附合规自检清单 |

### 1.3 非功能需求

- 兼容性：Windows 桌面，Python 3.12；ffmpeg 由 imageio-ffmpeg 自带，零系统依赖。
- 可观测：每个阶段独立日志、可单独运行、可跳过（--skip）。
- 稳定性：镜头切分双引擎（scenedetect 主 / cv2 回退）；无切点时整段视为一个镜头。
- 合规：内容层必须原创（仅借鉴镜头语言），真人形象须授权。

## 2. 架构设计

### 2.1 总体架构

```
                    ┌─────────────────────────────────────────────────┐
                    │                 pipeline（核心包）                │
  视频输入           │  stage1_parse ─▶ stage2_structurize ─▶           │
 ─────────▶ CLI(run_all.py)  ──────▶  stage3_assets ─▶ stage4_generate │
                    │                                  ├─ 通用平台模板   │
                    │                                  └─ h3_export     │
                    └───────────────┬──────────────────┬────────────────┘
                                    │                  │
                          ComfyUI 节点层           H3 提交工具
                         comfyui_nodes.py      tools/submit_minimax_h3.py
```

- **数据流**：每个阶段的产物是磁盘上的 JSON（shots → storyboard → assets → prompt pack），
  阶段之间零内存耦合 → 天然支持中断续跑与人工修订。
- **双出口**：阶段4 按 `generate.platform` 分发：
  - 通用平台（seedance/kling/veo/jimeng）→ `prompt_pack.md/.json`
  - `minimax_h3` → 六段式提示词 + 逐镜 API payload + 资产清单（`pipeline/h3_export.py`）

### 2.2 模块划分

| 模块 | 职责 | 依赖 |
|---|---|---|
| `common.py` | 配置加载、ffmpeg 定位、视频探测、JSON/日志 | 标准库 + PyYAML + cv2 |
| `stage1_parse.py` | 抽帧、镜头切分、关键帧 | ffmpeg、scenedetect/cv2 |
| `stage2_structurize.py` | 音轨抽取、ASR、VLM 描述、分镜表合并 | faster-whisper、vlm.py |
| `vlm.py` | OpenAI 兼容视觉理解客户端 | requests |
| `stage3_assets.py` | 人脸检测、感知哈希聚类、场景资产 | OpenCV |
| `stage4_generate.py` | 平台注册表 + 通用提示词模板 | - |
| `h3_export.py` | H3 六段式提示词 + payload + 资产校验 | cv2 |
| `comfyui_nodes.py` | ComfyUI 节点包装（JSON 进出） | 上述模块 |
| `tools/submit_minimax_h3.py` | H3 API 提交与轮询 | requests |

### 2.3 关键技术决策（ADR）

| 决策 | 选择 | 理由 |
|---|---|---|
| 镜头切分引擎 | scenedetect 0.6.7.1 主 / cv2 直方图回退 | 帧级精确；双引擎防单点失败 |
| OpenCV 版本 | opencv-python-headless<5 | OpenCV 5.0 移除 Haar CascadeClassifier；headless 免 GUI 依赖 |
| ASR | faster-whisper（CPU int8） | 本地推理、无云依赖、tiny~medium 可配 |
| 视觉理解 | VLM 可选（dashscope/openai 兼容） | 无 Key 时降级为字段留空，不阻断管线 |
| 角色聚类 | Haar + dHash 贪心聚类 | 零额外模型下载；鲁棒性足够原型 |
| H3 提示词 | 六段式模板（非 LLM） | 对齐生态规则；确定性、可审计、无 API 成本 |
| ffmpeg | imageio-ffmpeg 自带二进制 | Windows 无系统依赖 |

## 3. 数据契约

### 3.1 shots.json（阶段1）

```json
{
  "video": "绝对路径", "duration": 12.0, "scene_method": "scenedetect",
  "shots": [{"id": 0, "start": 0.0, "end": 4.0, "keyframes": ["keyframes/shot_000_002.00.jpg"], "dialogue": []}]
}
```

### 3.2 storyboard.json（阶段2）

在 shots 基础上：每镜增加 `dialogue: [{start,end,text}]` 与
`visual: {scene, characters[], action, costume, props[], camera, lighting, music_note}`。

### 3.3 assets.json（阶段3）

```json
{
  "characters": [{"id": "c0", "name": "角色0", "ref_images": ["assets/faces/..."], "source_shots": [0], "ref_time": 0.0}],
  "scenes": [{"id": "s0", "shot_ids": [0], "ref_images": ["assets/scenes/shot_000.jpg"]}],
  "props": []
}
```

### 3.4 minimax_h3/（阶段4-H3）

- `payloads/shot_XXX.json`：H3 `POST /v2/video_generation` 请求体（含 `_meta` 供工具剥离）。
- `assets_manifest.json`：资源映射（`c0=图1`）+ 限制常量快照。
- `validation_report.json`：逐资产合规校验结果（空数组=通过）。

字段级约束见 `schemas/`（JSON Schema）。

## 4. 模块设计要点

### 4.1 平台注册表（stage4）

```python
PLATFORM_HINTS = {seedance, kling, veo, runway, jimeng, minimax_h3: ...}
# main() 中：
if platform == "minimax_h3": h3_export.export_h3(...)  # 专用出口
else: 通用 build_shot_prompt 模板
```

新增平台 = 在 PLATFORM_HINTS 注册 + （如需专用格式）新增 builder 模块，改动面最小。

### 4.2 H3 导出核心（h3_export.py）

- `build_h3_pack(storyboard, assets, cfg, mode) -> {prompts, payloads, manifest, mapping_text, per_shot_refs, warnings}`
  —— 纯内存函数，CLI 与 ComfyUI 节点共用（单测友好）。
- `build_h3_prompt(shot, tags, cfg)` —— 六段式模板，台词 `<d>[中文] 原文</d>` 逐字保留。
- `build_shot_payload(shot, prompt, cfg, mode, first_frame)` —— 组装 content 数组，
  与官方规格一致（reference_image ≤9、i2v 时 ratio=adaptive）。
- `validate_image` —— 对照官方限制（格式/≤30MB/256-5760px/宽高比 0.4-2.5）返回警告。

### 4.3 ComfyUI 适配层（comfyui_nodes.py）

- 节点全部以 `STRING`（JSON 文本）进出，与既有 `ComfyUI-H3-Prompt-Builder` 风格一致。
- `ManjuH3Export` 不依赖文件系统（除可选 workdir 校验），可直接在 ComfyUI 中接入上游节点 JSON。
- 提供 `--self-test` 入口，脱离 ComfyUI 环境可验证节点逻辑。

## 5. 质量与测试策略

| 层级 | 方式 | 命令/位置 |
|---|---|---|
| 单元自检 | H3 导出六段式/role/映射断言 | `python -m pipeline.comfyui_nodes --self-test` |
| 冒烟测试 | 合成三段视频 → 3 镜头 | `samples/make_test_video.py` + `run_all.py` |
| 静态视频兜底 | 无切点 → 1 镜头 | `samples/face_test.mp4` |
| 资产链路 | 人像视频 → 1 角色 + 场景 | 同上 |
| 产物回读 | 从不同路径（Read/脚本）回读 JSON 校验结构 | 人工 + 脚本 |

已知限制（对应路线图）：
- Haar 级联仅正/侧脸可靠；遮挡、背影漏检。
- 服装/道具抽取为人工补充字段。
- 音频（BGM/环境音）为占位字段（N/A），未做自动分析。

## 6. 部署与发布

- **独立运行**：目录即应用；`.venv` 内依赖，`run_all.py` 入口。
- **ComfyUI 集成**：复制 `comfyui/` 到 `ComfyUI/custom_nodes/`，重启即可；依赖需装入 ComfyUI 的 Python 环境。
- **外部服务调用**：`pipeline` 包可被任何 Python 进程 import（`sys.path` 加入工程根即可）。
- **配置管理**：`config.yaml` 为唯一配置源；API Key 一律走环境变量（不落盘）。

## 8. 合规设计（红线内置）

1. README 与每次导出的提示词包均附**合规自检清单**。
2. H3 导出在 detailed_description 中按 `audio_text_policy` 自动处理字幕/BGM 策略。
3. 本工程只产出"提示词与资产"，不自动抓取或复刻他人成片内容；输入视频须为用户有权使用的内容。
